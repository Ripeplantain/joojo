# Align Seed Schema and Import Video Metadata

## Goal

Fix the schema/data mismatches found after seeding Sanity, add support for the provided
video metadata, import the generated `video` documents with the Sanity CLI, and verify
document counts and validation afterwards.

## Skills Read

- `sanity-best-practices`
- `sanity-best-practices/references/schema.md`
- `sanity-migration`
- `sanity-migration/references/general.md`

## Code and Data Inspected

- `studio/schemaTypes/documents/lesson.ts` currently defines `poster`, while
  `seed/seed-sanity.json` lessons use `thumbnail`.
- `sanity/lib/queries.ts` currently projects `poster`.
- `studio/schemaTypes/documents/instructor.ts` currently defines `bio` as `text`, while
  `seed/seed-sanity.json` instructors store `bio` as Portable Text blocks.
- `studio/schemaTypes/index.ts` has no `video` document type.
- `studio/structure.ts` has no Videos list item.
- `seed/video.json` has 120 metadata entries keyed by lesson slug:
  `id`, `title`, `channel`, `duration`, `query`.
- `seed/seed-sanity.json` has 120 matching lesson documents with `slug.current`,
  `videoUrl`, `thumbnail`, and `duration`.
- No existing migration or seed transform scripts are present.

## Decisions and Assumptions

1. Rename the lesson image schema field from `poster` to `thumbnail` to match the seeded
   content and the project language (`poster or thumbnail image`).
2. Update GROQ projections from `poster` to `thumbnail`.
3. Change instructor `bio` to Portable Text (`array` of `block`) because the seeded
   content already uses Portable Text and rich bios are content, not display-only strings.
4. Add a `video` document type with:
   - `id`: provider video ID from `video.json`
   - `url`: lesson `videoUrl`
   - `provider`: derived from URL, currently `youtube` for this seed
   - `title`, `channel`, `duration`, `query`: source metadata from `video.json`
   - `chapters`: array of `{ startSeconds, label }`
   - `chunks`: array of `{ startSeconds, text }`
5. Generate video import docs by joining `seed/video.json` to `seed/seed-sanity.json` on
   lesson slug. Use deterministic `_id` values derived from the video URL with invalid
   datastore characters stripped.
6. Since the provided video file has no transcript or chapter data, import `chapters: []`
   and `chunks: []`. This makes the content model ready without inventing transcript
   content.
7. Keep lesson-to-video lookup by URL rather than adding references from lessons to video
   documents, matching AGENTS.md: lessons link by video URL and video docs are internal
   lookup data.

## Requirements

- Use `defineType`, `defineField`, and `defineArrayMember` for all schema additions.
- Do not store video files in Sanity assets; keep only external video URL/metadata.
- Do not invent transcript chunks or chapters.
- Ensure the generated video seed is repeatable and importable with
  `sanity datasets import --replace`.
- Preserve already-imported course, lesson, instructor, and category documents.
- Verify counts from the live Sanity dataset after import.

## Security Considerations

- Sanity CLI operations write to project `1v8n2wrs`, dataset `production`.
- Do not read, print, or commit Sanity tokens.
- Generated video docs contain public YouTube metadata only.
- No browser-exposed tokens or client writes are introduced.

## Acceptance Criteria

- Studio schema includes `video`.
- Studio validation accepts seeded lesson `thumbnail` fields.
- Studio validation accepts instructor Portable Text `bio`.
- `seed/video-sanity.ndjson` contains 120 valid Sanity `video` documents.
- Sanity dataset counts after import:
  - `category`: 6
  - `instructor`: 5
  - `lesson`: 120
  - `course`: 10
  - `video`: 120
  - total for these five types: 261
- Type checking, lint, Studio build, and document validation complete or any failures are
  reported with exact output.

## Checks To Run

From repo root:

1. `node seed/build-video-seed.mjs`
2. `node --input-type=module -e "<local seed count check>"`
3. `npx tsc --noEmit`
4. `npm run lint`
5. `npm run build`

From `studio/`:

1. `npx sanity schema extract --force`
2. `npx sanity typegen generate`
3. `npm run build`
4. `npx sanity documents validate`
5. `npx sanity datasets import ../seed/video-sanity.ndjson --dataset production --replace`
6. Sanity count queries for `category`, `instructor`, `lesson`, `course`, `video`, and
   combined seeded types.

## Manual Test Steps

1. Run `cd studio && npm run dev`.
2. Open the Studio and confirm Videos appears in the content list.
3. Open one seeded lesson and confirm its thumbnail field is populated.
4. Open one seeded instructor and confirm the bio renders as Portable Text blocks.
5. Open one video document and confirm `url`, `id`, `title`, `channel`, and `duration`
   are populated, while `chapters` and `chunks` are empty.
